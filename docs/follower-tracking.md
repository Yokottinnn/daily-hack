# フォロワー数はどこに記録されているか

> **2026-09-21 に「300 人 のペースは間に合うか」を調べて分かったことをまとめる。**
> 推測で 2 回 外したので、**形を確定させて書き残す。**

## 実データはここ

```text
~/.openclaw/workspace/data/follower-snapshots/YYYY-MM-DD.json
```

**1 日 1 ファイル。** 中身はこの形（2026-09-20.json の実物）。

```json
{
  "taken_at": "2026-09-20T15:35:49.558Z",
  "username": "heng_ji31590",
  "count": 266,
  "followers": ["0025563h", "01koara", "…"]
}
```

| キー | 中身 |
| --- | --- |
| `count` | **人数はここ。** これを読む |
| `followers` | **ハンドルの配列。** 人数ではない |
| `taken_at` | UTC。**JST では翌日の 00:35 ごろ**に当たる |

### `followers` を人数だと思って読むと必ず外す

**実際に外した。** こう書いていた。

```javascript
// 危ない: `followers` は配列なので ?? がここで止まり、Number(配列) = NaN になる
const n = Number(j.followers ?? j.follower_count ?? j.count);

// 安全: 人数のキーを先に見る
const n = Number(j.count ?? j.follower_count);
```

**`??` は `null` / `undefined` のときだけ次へ進む。** 配列は「在る」ので止まる。

## 死んでいるファイルがある。**読まないこと**

```text
~/.openclaw/workspace/data/follower-history.json   ← **2026-05-23 で止まっている**
```

**最後の行が誤読で、そのまま残っている。**

```text
2026-05-22   51 人
2026-05-23    0 人   ← -51。明らかな誤読
（以降 4 か月 記録なし）
```

**このファイルを信じる仕組みがあれば「フォロワー 0 人」と判断する。**
4 か月 誰にも気づかれていない。**消す前に、何が読んでいるかを洗うこと。**

## 記録が飛んでいる期間がある

`follower-snapshots/` は **53 ファイル**あるが、**日付が連続していない。**

```text
2026-09-20.json
2026-09-08.json     ← **9/9 〜 9/19 の 11 日分 が無い**
2026-09-07.json
2026-08-29.json
…
```

**欠けている 11 日間は、48 本 のジョブが外れていた期間と一致する**
（2026-09-09 に外れ、2026-09-20 に気づいた。`CLAUDE.md` の
「落ちたジョブは `ops/data/autoload-jobs.txt` で戻す」を参照）。

### だから「直近のペース」は出せない

2026-09-21 時点で使える点は **9/7・9/8・9/20 の 3 つだけ。**
**9/8 → 9/20 の 12 日 平均（3.25 人/日）より細かくは出せない。**

**「直近 3 日 は伸びている」のような話は、いまのデータでは言えない。**
言ったらそれは推測である。

## 目標に対する位置（2026-09-21 時点）

| | |
| --- | --- |
| 目標 | **9/30 に 300 人** |
| いま | **266 人**（9/20 の記録。`record_age_days: 1`） |
| 残り | **34 人・9 日 → 3.78 人/日 が必要** |
| 12 日 平均（3.25）のまま | **295 人。5 人 足りない** |

**「ほぼ届く」ではなく「わずかに足りない」。** 余裕はゼロ。

## 読むときに打つもの

```bash
# 人数だけを日付順に
for f in ~/.openclaw/workspace/data/follower-snapshots/*.json; do
  node -e 'const j=require(process.argv[1]);
           console.log(j.taken_at.slice(0,10), j.count)' "$f"
done | sort
```

**クラウドからは Mac のファイルを直接 読めない。** `ops/tasks` を 1 本 足して
レポートに出す（`x117-read-snapshot-dir.sh` がその形）。
