# フォロワーを増やす 3 つのループ

リプライ営業（`comment-warmup`）で接点を作ったあと、**その接点をフォロワーに変える**部分が
まるごと欠けている。ここを埋める。

| ループ | いまの状態 | このドキュメントで決めること |
| --- | --- | --- |
| ① 会話を続ける | **未実装**。自分のリプへの返信を拾えていない | 何往復まで／何に返すか |
| ② フォロー返し | **未実装** | 誰に返すか／どれだけ待つか |
| ③ アンフォロー | **未実装** | いつ外すか／誰を外さないか |

**3 つは順番に効く。** 会話が続くと相手がフォローし、フォロー返しで関係が固定され、
返らない相手を外すことで次のフォロー枠が空く。どれか 1 つでは回らない。

## 前提: 凍結したら全部止まる

自動フォロー・自動アンフォローは、X が最も厳しく見る挙動である。
**とくに follow → unfollow を短期間に繰り返す動き（churn）は検知されやすい。**

このドキュメントの数値はすべて**安全側に倒してある。** 上限に近づける価値より、
止まらないことの価値が大きい。**増やすのは 1 週間 異常が無いことを確認してから。**

## ① 会話を続ける（返信への返信）

### いまの穴

`incoming-reply-watcher` は**自分の投稿に来たリプ**を拾う。しかし
**自分が打ったリプに相手が返してきた場合**を拾っていない。

```text
相手の投稿
  └─ 自分のリプ（comment-warmup）
       └─ 相手の返信      ← ここが拾えていない。会話が 1 往復で終わる
```

リプライ営業の目的は接点を作ることなので、**相手が反応してくれた瞬間が最も重要**である。
そこで会話を打ち切っているのは、いちばんもったいない止め方になっている。

### 決めること

| 項目 | 値 | 理由 |
| --- | --- | --- |
| 追う深さ | **自分の 2 手目まで**（相手→自分→相手→自分で終了） | 延々と続けるとしつこい。2 手目で自然に終わる |
| 返す条件 | 質問・呼びかけ・具体的な話題がある | 「ありがとう」「👍」だけには返さない |
| 返さない条件 | 定型の挨拶のみ／宣伝リプ／絵文字のみ | 会話が成立していない |
| 同一相手 | **1 日 1 回まで** | 粘着と判定されるのを避ける |
| 開始時の総量 | **5 件/日** | 既存のリプ枠とは別カウント |
| 上限 | 10 件/日 | 1 週間 異常なしで引き上げ |
| 遅延 | 検知から **2〜10 分**のランダム | 即レスは bot に見える |

### 中身の条件

既存のリプと同じ規定に従う。**新しく決めることはない。**

- v3 ブランド準拠（マスコット＝ハッカー子 / 一人称＝アタシ）
- **相手の発言に具体的に触れる。** 定型文はブロックを招く
- **URL を貼らない。** リプに URL を入れると露出が落ちる

## ② フォロー返し

### 決めること

**フォローされてから即座に返さない。** 即時のフォロー返しは自動化の証拠になる。

| 項目 | 値 | 理由 |
| --- | --- | --- |
| 遅延 | **6〜24 時間**のランダム | 人間の巡回に見せる |
| 上限 | **20 件/日** | 相手が先にフォローしているぶん、能動フォローより安全 |
| 実行の分散 | 1 回の実行で最大 5 件、時間を空ける | 一斉フォローは検知されやすい |

### 返す基準

**基準は緩くする。** 目的はフォロワーを増やすことであり、厳しくすると母数が減る。
**除外だけを決めて、当たらなければ全部返す。**

| 除外する | 判定 |
| --- | --- |
| 実体の無いアカウント | 投稿 0 件 **かつ** フォロワー 10 人未満 |
| 相互フォロー狙いの回遊 | フォロー数 ÷ フォロワー数 が **10 倍を超える** |
| 宣伝専用 | bio がリンクのみ、または投稿の大半が同一 URL |
| 明らかに層が違う | 投資勧誘・出会い系・アダルトの語が bio または固定投稿にある |
| 日本語圏でない | 直近 10 投稿の大半が日本語でない |

**判定はルールベースで行い、LLM を使わない。** 数値と文字列一致で足りる。
判断がつかないものは**保留リストに入れて、フォローも除外もしない**。人が見て決める。

> LLM を使うと、フォロー返しの件数に比例して費用が乗る。得られる精度に見合わない。
> 同じ理由で、15 分クイックリプライの検知も LLM を使わない設計にしてある。

## ③ アンフォロー

### 決めること

| 項目 | 値 | 理由 |
| --- | --- | --- |
| 待つ期間 | **14 日** | 通知を見逃す人がいる。7 日は短い |
| 上限 | **10 件/日** | フォロー数より少なくする。churn を避ける |
| 同日の混在 | フォローとアンフォローを**同じ実行で行わない** | 連続すると churn に見える |
| 記録 | 外した相手を残す | **二度とフォローしないため。** 再フォローは最も嫌われる |

### 外さない相手

| 除外 | 理由 |
| --- | --- |
| 相互フォロー | 当然 |
| こちらのリプに反応したことがある | 関係が生きている |
| 手動で登録した VIP リスト | 大手アカウントなど、返されなくても繋がっておきたい相手 |
| フォローから 14 日未満 | 判定の対象外 |

## 効果の測定

**何が効いたか分からないまま量を増やさない。**

| 記録項目 | 用途 |
| --- | --- |
| フォロワー数の日次推移 | すべての土台。**`follower-snapshot` が止まっているので先に戻す** |
| フォロー返しの実施数と、その後の継続率 | 基準が緩すぎないか |
| アンフォロー実施数 | churn の量を把握する |
| 会話が 2 往復以上続いた件数 | ①の効果 |
| 会話が続いた相手がフォローしたか | **①→②の接続が効いているかの唯一の証拠** |

## コスト

単価は `docs/recurring-job-costs.md` の実測値（リプ 1 件 **$0.00417**・Haiku 4.5）による。

| ループ | LLM を使うか | 1 回 | 1 日 | 1 か月 |
| --- | --- | --- | --- | --- |
| ① 会話を続ける（開始 5 件/日） | **使う**（返信生成） | $0.00417 | $0.021 | **$0.63** |
| ① 上限まで（10 件/日） | 使う | $0.00417 | $0.042 | **$1.25** |
| ② フォロー返し（20 件/日） | **使わない** | $0 | $0 | **$0** |
| ③ アンフォロー（10 件/日） | **使わない** | $0 | $0 | **$0** |

**追加コストは①だけ**で、開始時 **月 $0.63**、上限まで引き上げても **月 $1.25**。
現行の運用（月 $1.13〜1.25）と合わせて **月 $1.8〜2.5** に収まる。

②③をルールベースにしたのはこのため。**LLM で判定すると件数に比例して費用が乗る。**

## 実装の順番

**①→②→③ の順に入れる。** ②③はフォロー操作を伴うため、凍結リスクが①より高い。

1. **`follower-snapshot` を戻す。** これが無いと、何をやっても効果が測れない
2. ① 会話を続ける（DRY_RUN で生成パスを確認してから有効化）
3. ② フォロー返し（1 週間 ①が無事に回ってから）
4. ③ アンフォロー（②の 14 日後。それより前は対象が存在しない）

**3 と 4 の間は必ず空ける。** 同時に入れると churn になる。
