## ⚠️ この月に見つかった不具合 4 件

**どちらも「黙って間違った数字を出していた」ものなので、先に書く。**

### ① 週次の PV レポートが 2 週間 以上 落ちていた（直した・PR #741）

`weekly-pv-report` が **9/14・9/21 とも失敗**していた。原因は
累積 JSON を `jq --argjson` で渡していたこと（`jq: Argument list too long`）。
**Actions は赤くなっていたが、誰も見ていなかった。**

### ② PV の総数が下限値だった（直した・PR #743）

`httpRequestsAdaptiveGroups` の `limit: 200` が**毎日 飽和**していた
（26 日で 198.6 行/日）。`orderBy: sum_visits_DESC` なので裾が毎日 切り捨てられていた。

上限を 5000 にして取り直した差。**上位記事の順位は変わらない。**

| | 壊れていた値 | 正しい値 | 差 |
| --- | --- | --- | --- |
| 総 visits | 11,702 | **13,778** | +2,076（+18%） |
| 総 requests | 12,472 | **21,503** | +9,031（**+72%**） |
| 全パス数 | 5,163 | **8,644** | +3,481 |

### ③ 週次レポートの PV は**別サイトの数字だった**（原因 判明・t196）

同じ 9 月について **Zone Analytics が visits 13,778、Web Analytics が PV 100。**
原因は `cf_site_tag()` の推測ではなく、**逆だった。**

| 確かめたこと | 結果 |
| --- | --- |
| アカウントの RUM サイト | **1 件だけ**（`fieldbeside.com` / tag `73990e57…`） |
| `BaseLayout.astro` のビーコン token `0dc312c5…` | **アカウントに存在しない** |
| その token で引く | PV **0**（データが無い） |
| いま選ばれている tag で引く | PV 100・`/posts/…` **0 件** ← 週次に出ていた数字 |

**サイトに貼ってあるビーコンが、存在しないサイトを指している。**
だから記事ページの PV が 0 だった。**RUM データはそもそも 1 件も取れていない。**

**直し方は未決**（利用者の判断待ち）。選択肢は 3 つ。

1. daily-hack 用の Web Analytics サイトを作って、ビーコンの token を差し替える
   （Cloudflare への**書き込み**が要る）
2. 既存の `73990e57…` に寄せる（**fieldbeside.com 本体と数字が混ざる**）
3. **RUM をやめて Zone Analytics に一本化する**（④ の内訳が入ったので実用になった）

### ここが 9 月のいちばんの課題

**表示は 1.8 倍 に伸びたのに、クリックは減っている。**
順位帯を見ると **4〜10 位に 53 記事・表示 1,064** が溜まっていて、

`lalaport-guide-2026` が **8.6 位・表示 562・クリック 21（CTR 3.7%）**で表示の約半分を占める。
8 月ぶん（引き算）では 439 表示・25 クリック（5.7%）だった。

**ただし「タイトルが悪い」と決めつけない。** 記事を開いて確かめたところ、
**`title` は先頭が主要検索語「ららぽーと売上ランキング」そのままで、既に最適に近い。**
順位もほぼ動いていない（8.3 → 8.6 位）のに表示だけ 439 → 562 に増えているので、
**より広い・関係の薄い語で出るようになったぶん CTR が薄まった**という読みのほうが素直。

そのうえで、記事側で直せるものは直した（PR #751）。
