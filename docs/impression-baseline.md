# 告知の表示回数は、どれくらいが普通か

> **2026-09-21 に「投稿が伸びていない気がする」と言われて調べた。**
> **結論: 絞られていなかった。** だが土台が薄いので、ここに記録を足していく。

## 実測（`x-impressions.jsonl` ／ 3 時間おきに記録）

| 経過 | 格安スーパー（9/21 18:23） | 歩いてポイ活（9/21 00:27） |
| --- | ---: | ---: |
| **〜3h** | **35** | 29 |
| **〜6h** | **57** | 48 |
| 23h | — | **165** |

**同じ経過時間で比べると、削除して出し直した格安スーパーのほうが上。**
**「削除直後の再投稿で X に絞られた」形跡は無い。**

## 比べるときに踏んだ穴（**2 つとも私の検査の誤り**）

### ① 近い記録を拾う許容幅が広すぎた

`x127` の表で `~12h` と `~48h` の列に **`~6h` と同じ点が二重に出ていた。**

```javascript
// 危ない: 許容が h*0.5+1.5 なので、5.2h の点が 12h の枠に入ってしまう
const d = Math.abs(p.age - h); if (d < bd && d <= h * 0.5 + 1.5) { ... }

// 直すなら: その枠に「届いていない」ものは捨てる
if (p.age >= h * 0.75 && p.age <= h * 1.25) { ... }
```

**投稿からまだ 5 時間 しか経っていないのに、12h と 48h の数字が出ていた。**
存在しない記録が表に載るので、**そのまま読むと伸びが鈍く見える。**

### ② スレッド 2 本目の表示回数は取れていない

**`[2/2]` の URL を開くと、X はスレッドの親（`[1/2]`）から描画する。**
最初の `article` の `aria-label` を読むと、**2 本とも同じ数字**になる。

```
[1/2] 2101965436426564045  63 件の表示
[2/2] 2101965516718187002  63 件の表示  ← **[1/2] の値を読んでいる**
```

**`x-impressions.js` も同じ読み方をしている。** 2 本目の実数は未取得。
直すなら、`article` を複数 取って **`status/<id>` のリンクで本人のものを選ぶ。**

## 土台が薄い

記録がある告知は **8 本 中 2 本だけ**。
`com.dailyhack.x-impressions` を入れたのが 2026-09-21 なので、
それ以前（IKEA・モーニング・サウナ・海外リゾート・電気代・値上げ）は空。

**「いつもこの程度」と言うには母数が足りない。** 数本 溜まるまで判断しない。

## 時間帯の話は、まだできない

出した時刻は **00:27 と 18:23 の 2 点**しかない。
**2 点で「夕方が弱い」とは言えない。**
時間帯を言うには、同じ種類の告知を違う時刻に出した記録が要る。

## 本当の論点

1 本あたりではなく、**アカウント全体の到達**。
フォロワー **266 人** に対して **23 時間 で 165 表示**。
**告知の中身ではなく、届く相手の数の問題**に見える。
