# 事実として報告してよいもの・いけないもの

CLAUDE.md 最上位ルール 11 の実体。

2026-09-06、**同じ日に 3 回、事実でないものを事実として報告した。**
利用者から「**報告の虚偽をしていたということ？**」と問われた。
仕組みで防ぐために、何が起きたかと判定手順をここに残す。

## 何が起きたか

| 私の報告 | 根拠にしたもの | 実際 |
| --- | --- | --- |
| 「返信の実投稿は **0 件**」 | 21:52 以前に生成されたレポート | **22:03 に 1 件 出ていた** |
| 「確認した。0 件は事実」 | **同じ古いデータを 3 つ**並べた | 確認になっていない |
| 「今日 **3 件** 出た」 | `heartbeat.json` の `posted_today` | **1 件**（キューの一次情報で確定） |

利用者が投稿 URL を 1 本 提示しただけで、すべて崩れた。

### なぜ間違えたか

1. **レポートの生成時刻を見なかった。** `ops/tasks` の出力はファイルであり、
   **開いた時刻ではなく生成された時刻の状態**を書いている。
2. **同じ経路から 3 回 読んで「3 つの根拠」と呼んだ。** すべて同じスナップショット由来で、
   独立していない。**数を並べても裏取りにならない。**
3. **`posted_today` はログの行数**だった。2 つのログに同じ投稿が書かれれば 2 と数える。
   **投稿の数ではない。**

## 一次情報はどれか

**「実際に X へ出たか」を判定してよいのは、次の 2 つだけ。**

| 一次情報 | 場所 | 何が分かるか |
| --- | --- | --- |
| **キューの `x_tweet_id` / `tweet_id`** | `~/.openclaw/workspace/data/post_queue.json` | **その ID で X に出ている**（ID があれば投稿は成立している） |
| **投稿 URL の実物** | `https://x.com/<handle>/status/<id>` | 開いて存在すれば確定 |

**次のものは一次情報ではない。事実として報告しない。**

- `heartbeat.json` の `posted_today` — **ログの行数**。二重計上する
- `*.log` の grep 件数 — 再試行やリトライが行ごとに残る
- `ops/tasks` の過去のレポート — **生成時刻の状態**であって、いまではない
- 「ジョブがロードされている」「rc=0」 — **動いたことは出たことではない**

## 報告の前に必ず打つ

```bash
# 1. そのレポートは いつのものか
grep -m1 -E '[0-9]{4}-[0-9]{2}-[0-9]{2} [0-9]{2}:[0-9]{2}' /tmp/<レポート>.md
#    → 現在時刻と比べる。**数分でも古ければ、それは「いま」ではない**

# 2. 数はキューから数える（ログではない）
/usr/local/bin/node -e '
const q=JSON.parse(require("fs").readFileSync(process.argv[1],"utf8"));
const t=new Date(Date.now()+9*3600*1000).toISOString().slice(0,10);
const rows=(q.queue||[]).filter(e=>e&&(e.kind==="comment"||e.kind==="reply")&&(e.x_tweet_id||e.tweet_id));
console.log("累計 "+rows.length+" / 今日 "+rows.filter(e=>String(e.posted_at||e.created_at||"").slice(0,10)===t).length);
' ~/.openclaw/workspace/data/post_queue.json
```

## 言い方の規定

- **「0 件」と言うときは、いつ時点の 0 なのかを必ず添える。**
  「21:52 時点で 0 件」は正しい。「0 件」は間違いになりうる。
- **推定と実測を混ぜない。** 数字の出どころ（キュー／ログ／レポートの生成時刻）を並記する。
- **利用者が反証を出したら、まず自分の根拠の鮮度を疑う。** 反論を先に組み立てない。
- **0 なら 0 と言う。** 見栄えのために言い換えない。
