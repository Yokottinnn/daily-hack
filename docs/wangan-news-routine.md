## 手順（この順で、全部やる）

1. **最新にする**: `git fetch origin main`。作業ブランチに未マージのコミットが無いことを `git log origin/main..HEAD` で確かめてから `git checkout -B <作業ブランチ> origin/main`
2. **`blog-article` スキルを読む**（最上位ルール 6）
3. **話題を集める**: `node scripts/wangan-news/collect.mjs --out /tmp/wn.json`
   - `skip`（事件・事故・古い写真ページなど）と `covered`（もう書いた）は飛ばす
   - `referenceOnly`（とよすと等のまとめ）は**話題があった合図にだけ使う**。文・写真・数字を写さない
   - PR TIMES の検索は**本社の住所で当たる無関係のリリースが多い**（有明・豊洲に本社がある会社）。**湾岸で起きること**だけ選ぶ
4. **選ぶ（3〜5 本）**: 次の順で優先する
   1. 期限があり、これから来るもの（イベント・キャンペーン・開業）。**日付が近いもの**から
   2. 無料・先着・割引など、読者の得が数字で言えるもの
   3. 生活に効く変化（交通・工事・公共施設・区の制度）
   - **同じ施設の話題は 1 日 1 本**。終わったイベントの報告は書かない
5. **一次情報で裏を取る**: プレスリリース本文（PR TIMES）・施設の公式ページ・区や都のお知らせ。Google ニュースの記事は根拠にしない
   - **日付は必ず年から書く**（「2026年10月25日（日）」。title・見出し・カード・表も。2026-10-25 利用者の指示）
   - 日付・時間・場所・料金・先着数・条件は**一次情報の表記どおり**。分からないものは書かない（制作の裏側も書かない）
6. **書く**（1 本につき）: 型は下の「記事の型」
   - slug は内容が分かる英語（`<施設>-<中身>-2026`）。`category: ["wangan-life"]`、`tags` の先頭は **`湾岸ニュース`**、地名・施設名を続ける
   - title は「施設名＋中身｜日付・数字の入った得」。description に数字を入れる（160 字以内）
   - 冒頭は読者の疑問 2 つ → 「だからアタシがまとめた」→ `hakkako-says` で一番大事なこと
   - `30秒で分かる` の写真カードは 3 枚か 6 枚。仕様表（施設・期間・場所・時間・行き方）。施設名の左にロゴ（最上位ルール 17）
   - もらえる物・条件・先着の数は表にする。迷いやすい点は `checklist`
   - 関連記事を本文中に 2 か所（既存の湾岸記事）
   - 出典を `source-note` に。画像は `figcaption > cite` で出典
7. **画像**: プレスリリース・主催者の素材を `public/images/<slug>/photos/` に置き、`_manifest.json` に出典 URL・権利表記・取得日を書く。
   **表紙は主催者・公式の元の画像をそのまま使う**（2026-10-25 利用者「表紙は記事のようにしないで、速報感や公式感が出るようにオリジナルの画像を使って欲しい」）。
   `python3 scripts/gen-news-cover.py <公式の画像> public/images/<slug>/eyecatch.jpg --y <0〜1>`。文字は足さない。チラシ・キービジュアル・告知画像を選ぶ。
   **縦長でも横長でも 16:9 に切り取って画面いっぱいにする**（2026-10-25 利用者「縦長の画像だろうとすべてブログにマッチするように。
   基本的には切り取った方がいい。最悪は縦長に画像をはめるか」）。`--y` で残す高さを決める（0 = 上端。チラシは題名と日付が入る 0〜0.1 が多い）。
   **題名・日付・ロゴが端で切れていないかを見て `--y` を動かす。** 切り取ると要の部分がどうしても入らないときだけ `--fit`（全体を収め、余白をぼかす）
   **gen-photo-hero.py（見出しを載せた記事風の表紙）は湾岸ニュースでは使わない。** できた表紙を必ず開いて見る
7-B. **SNS の声を拾って載せる**（2026-10-25 利用者「X や YouTube、インスタで特集されている投稿を実際に探してきて、どんなことを言っているかまとめて掲載して。すべての湾岸ライフ記事で同じように」）:
   - **X**: Mac に `ops/tasks/t331-wangan-news-x-voices.sh` の形で検索させる（話題順・最新順。syndication API で本文・投稿者・日付を確かめる）
   - **YouTube**: クラウドから検索結果（`ytInitialData`）を読み、**oEmbed でタイトルと投稿者を照合**してから埋め込む
   - **Instagram**: Mac の Chrome が未ログインで読めない。読めるようになるまでは載せない
   - 記事に「SNS ではこう言われている」の節を置き、**投稿の言っていることを 3〜5 行でまとめる**＋実投稿を埋め込む。実在する投稿だけ。宣伝より体験の投稿を選ぶ
   - Mac の結果を待つあいだに先に公開してよい。届いたら同じ日のうちに足して出し直す
8. **検査**: `npm run build`（Complete! を確かめる）→ `npx astro check --minimumSeverity error` → `check-article-ux.py` → `check-md-bold.py` → アンカー切れの照合
9. **公開**: まとめて 1 本の PR（その日の記事すべて）→ CI → マージ。**PR の bot コメントのプレビュー URL** を記事ごとに取る（最上位ルール 16）
10. **報告**（日本語・最上位ルール 22）: 「レビューのお願い」を先頭に、記事ごとに見出し＋プレビュー URL（記事パス付き）＋見てほしい点 2 つ。
    最後に費用の行「費用: 1 回 $0・1 日 $0・1 か月 $0（Console 課金。この作業はプランの利用枠の中）」
11. **引き継ぎ**: `npm run handoff -- "湾岸ニュース <日付>: <本数> 本" --next "…"`

## 記事の型

構成の見本は `src/content/posts/aquacity-rilakkuma-xmas-2026.md`（**港区の施設なので非公開にした。構成だけ真似る。題材は真似ない**）。
冒頭（疑問 2 つ → だからまとめた → ハッカー子の一番大事なこと）→ 30 秒で分かる写真カード 3 枚 → 期間と場所の仕様表 → もらえる物・条件・先着数の表 → 日付限定の催し → **SNS ではこう言われている（X・YouTube のまとめと埋め込み）** → 回り方の checklist → 出典 → 締めの一言。表紙は公式の元の画像。

## 書かないもの

- 事件・事故・訃報・相場・求人・企業の決算
- 湾岸に本社があるだけで、湾岸と関係のないリリース
- 終わったイベントの報告（「終了」とも書かない）
- 一次情報が見つからない話題（まとめサイトだけが出どころのもの）
