## 勝ち筋（とよすとと同じことをしない）

- **範囲を湾岸全体に広げる**: 晴海・勝どき・月島・豊洲・有明・お台場・東雲・辰巳・芝浦・天王洲。とよすとは豊洲の中だけ
- **「お得」の切り口を必ず 1 つ入れる**: 無料か・先着何個か・何円で何がもらえるか・いつ行けば空いているか
- **毎日の記事は入口**: 本文の中で既存の湾岸記事（スーパー・サウナ・花火・お金・ドローンショー）や成果リンクのある記事へ送る

## 手順（この順で、全部やる）

1. **最新にする**: `git fetch origin main`。作業ブランチに未マージのコミットが無いことを `git log origin/main..HEAD` で確かめてから `git checkout -B <作業ブランチ> origin/main`
2. **`blog-article` スキルを読む**（最上位ルール 6）
3. **話題を集める**: `node scripts/wangan-news/collect.mjs --out /tmp/wn.json`
   - `skip`（事件・事故・古い写真ページなど）と `covered`（もう書いた）は飛ばす
   - `referenceOnly`（とよすと等のまとめ）は**話題があった合図にだけ使う**。文・写真・数字を写さない
   - PR TIMES の検索は**本社の住所で当たる無関係のリリースが多い**（芝浦・有明に本社がある会社）。**湾岸で起きること**だけ選ぶ
4. **選ぶ（3〜5 本）**: 次の順で優先する
   1. 期限があり、これから来るもの（イベント・キャンペーン・開業）。**日付が近いもの**から
   2. 無料・先着・割引など、読者の得が数字で言えるもの
   3. 生活に効く変化（交通・工事・公共施設・区の制度）
   - **同じ施設の話題は 1 日 1 本**。終わったイベントの報告は書かない
5. **一次情報で裏を取る**: プレスリリース本文（PR TIMES）・施設の公式ページ・区や都のお知らせ。Google ニュースの記事は根拠にしない
   - 日付・時間・場所・料金・先着数・条件は**一次情報の表記どおり**。分からないものは書かない（制作の裏側も書かない）
6. **書く**（1 本につき）: 見本は `src/content/posts/aquacity-rilakkuma-xmas-2026.md`
   - slug は内容が分かる英語（`<施設>-<中身>-2026`）。`category: ["wangan-life"]`、`tags` の先頭は **`湾岸ニュース`**、地名・施設名を続ける
   - title は「施設名＋中身｜日付・数字の入った得」。description に数字を入れる（160 字以内）
   - 冒頭は読者の疑問 2 つ → 「だからアタシがまとめた」→ `hakkako-says` で一番大事なこと
   - `30秒で分かる` の写真カードは 3 枚か 6 枚。仕様表（施設・期間・場所・時間・行き方）。施設名の左にロゴ（最上位ルール 17）
   - もらえる物・条件・先着の数は表にする。迷いやすい点は `checklist`
   - 関連記事を本文中に 2 か所（既存の湾岸記事）
   - 出典を `source-note` に。画像は `figcaption > cite` で出典
7. **画像**: プレスリリースの素材を `public/images/<slug>/photos/` に置き、`_manifest.json` に出典 URL・権利表記・取得日を書く。
   表紙は `python3 scripts/gen-photo-hero.py <写真> public/images/<slug>/eyecatch.jpg "湾岸ニュース｜<地名>" <見出し1> <見出し2> <読む理由> <出典>`。
   写真の右下に © がある素材は `HERO_HANDLE_TOP=1` を付ける（© は消さない）。**できた表紙を必ず開いて見る**
8. **検査**: `npm run build`（Complete! を確かめる）→ `npx astro check --minimumSeverity error` → `check-article-ux.py` → `check-md-bold.py` → アンカー切れの照合
9. **公開**: まとめて 1 本の PR（その日の記事すべて）→ CI → マージ。**PR の bot コメントのプレビュー URL** を記事ごとに取る（最上位ルール 16）
10. **報告**（日本語・最上位ルール 22）: 「レビューのお願い」を先頭に、記事ごとに見出し＋プレビュー URL（記事パス付き）＋見てほしい点 2 つ。
    最後に費用の行「費用: 1 回 $0・1 日 $0・1 か月 $0（Console 課金。この作業はプランの利用枠の中）」
11. **引き継ぎ**: `npm run handoff -- "湾岸ニュース <日付>: <本数> 本" --next "…"`

## 書かないもの

- 事件・事故・訃報・相場・求人・企業の決算
- 湾岸に本社があるだけで、湾岸と関係のないリリース
- 終わったイベントの報告（「終了」とも書かない）
- 一次情報が見つからない話題（まとめサイトだけが出どころのもの）

湾岸ライフの記事の読者数・検索の表示回数（湾岸ニュースの記事）・湾岸ニュースから成果リンクのある記事への移動。
4 週間たったら、本数・X の告知を始めるかを利用者に聞く（費用を示してダイアログで）。
