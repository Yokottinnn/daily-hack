# 画像に直接コメントできるレビューページ

> **2026-09-20 に指示された。**
>
> > ブログ記事みたいに、作ってもらった画像の箇所を指定してコメントできる機能（システム）を作ってほしい

## なぜ作ったか

**X 告知画像の直しが、チャットの往復でしか伝えられなかった。**

ブログ記事は Cloudflare Pages のプレビューに下書きフィードバックで指摘を書き込める
（最上位ルール 16）。**画像にはその口が無い。** そのため

- 「4枚目画像の意味がわからない」「2枚目画像のタイトル名が意味わからない」のように
  **枚数で指す**ことになり、画像のどこを指しているのかが伝わらない
- 利用者が「コメントした」と言っても、**こちらには届いていない**ことが実際に起きた
  （通知キューが空のまま。同じ日に 3 回）

**画像の上に直接ピンを置ける場所を作れば、この往復は消える。**

## 何を作ったか

**claude.ai の Artifact として公開したレビューページ。**

| | |
| --- | --- |
| URL | https://claude.ai/artifact/1o7gjZZghit8kn3W4AXUdH |
| 置いてある画像 | 歩いてポイ活 4 枚 ／ 都心の格安スーパー 4 枚 |
| 保存先 | その Artifact の共有 DB（`db` capability）の `pins` コレクション |

### 利用者の側

1. 画像の**直したいところをクリック**する
2. その位置にピンが立ち、入力欄が開く
3. 書いて「コメントを置く」→ **自動で保存される**（送信操作は無い）
4. 直ったものは「対応済み」で消し込む。間違えたものは「削除」

ピンは画像ごとに 1 から番号が振られ、下のコメント一覧と対応する。
**未対応の件数が上部に常に出る。**

### Claude の側

**`ArtifactData` で読む。**

```text
ArtifactData(action="list", url="https://claude.ai/artifact/1o7gjZZghit8kn3W4AXUdH",
             collection="pins")
```

1 件は次の形で入っている。

```json
{ "target": "walk/2-waon.jpg", "slug": "walk-poikatsu-2026", "file": "2-waon.jpg",
  "x": 0.42, "y": 0.71, "text": "…", "done": false, "createdAt": "…" }
```

`x` / `y` は**画像の左上を 0、右下を 1 とした割合。** 枚数ではなく座標で指せる。

## 落とし穴

- **セッションは republish / コメントで起こされない。**
  `mint_failed` で durable wake subscription が登録できなかった
  （`ArtifactComments(action="watch")` も同じ）。
  **通知は来ない前提で、こちらから `ArtifactData` を読みに行く。**
- **画像はページと一緒に publish している**（`files` で `img/<slug>/<file>`）。
  **画像を作り直したら、同じファイルパスで publish し直す。**
  別のパスで publish すると URL が変わり、コメントが付いた場所と合わなくなる。
- **`db` を宣言した Artifact は組織内限定になる。** 公開リンクにはできない。
  利用者本人が開くぶんには問題ない。
- **コメントは Artifact に紐づく。** Artifact を削除すると DB ごと消える。
  残したい指摘は `.claude/skills/x-post-images/SKILL.md` のフィードバック表に写す。
