# 緊急依頼を Mac に埋もれさせない

## 何が起きたか（2026-08-15）

意図しないタイムライン投稿が出た。Jordan は**即座の削除**を求めた。
削除は X の UI で**ボタン 1 つ**の操作である。

にもかかわらず、**2 時間半のあいだ削除されなかった。** 最終的に Jordan 本人が手で消した。

```text
07:18  緊急停止の依頼を送信
07:21  犯人特定の依頼を送信
07:21  削除の依頼を送信          ← 本当に急ぐのはこれ
07:24  TTL 実装の依頼を送信
07:29  「削除だけやって」を再送
       → Mac は後発の TTL・heartbeat・プロンプト軽量化を先に処理
       → 削除の報告だけが一度も返らなかった
09:58  再送。応答なし
10:21  Jordan が自分で削除
```

## 原因

**1 操作で終わる緊急依頼を、他の依頼と同じ非同期経路に流した。**

1. **依頼を短時間に 5 件送った。** 最優先のものが列の後ろに埋もれた
2. **応答が無いことを検知する仕組みが無かった。** 返らないまま時間だけ過ぎた
3. **クラウドから X へ直接届かない**（egress 遮断）。代替手段が無く、待つ以外になかった
4. **「自分でやったほうが速い」を利用者に提示しなかった。** 待たせる判断を勝手に続けた

3 は環境の制約で変えられない。**変えられるのは 1・2・4 である。**

## これから守ること

### 1. 緊急依頼は 1 件だけ送る

緊急依頼を送ったら、**返答が来るまで他の依頼を送らない。**
別件が思いついても、緊急依頼が片付いてから送る。

キューは先入れ先出しではなく、**後から来たものが目立つ。**
まとめて送れば、最優先のものほど埋もれる。

### 2. 15 分で応答が無ければ、再送ではなく利用者に伝える

同じ依頼を投げ直すのは 1 回まで。それでも返らなければ、**Mac ではなく利用者に言う。**

**「待ちます」と黙らない。** 待っていること自体を報告し、待つ以外の道
（自分で操作する・別経路・中止）を `AskUserQuestion` で選べる状態にする。
これは最上位ルール 1 の「他者待ちで止まる場合もダイアログで出す」の具体化である。

### 3. 1 操作で済むことは、投げる前に利用者へ選択肢を出す

削除・停止・取り消しのような**取り返しに関わる 1 操作**は、
非同期経路に流す前に「自分でやりますか、依頼しますか」を提示する。

**利用者の手が最速であることは珍しくない。** 今回がまさにそれだった。
自動化の一貫性より、止血の速さを優先する。

### 4. 取り消し系は他の作業と混ぜない

削除・停止・ロールバックは、**それだけを単独で依頼する。**
同じメッセージに調査・実装・報告を混ぜない。混ぜると優先度が消える。

## 判定

**「削除しました」というテキストは完了の証拠にならない。**
URL が 404 / 削除済みであることを実際に確認した出力だけが証拠である。

これは OpenClaw が過去に虚偽の完了報告をした経緯があるためで、
[`docs/openclaw-recovery.md`](./openclaw-recovery.md) と同じ判定基準に揃えている。
