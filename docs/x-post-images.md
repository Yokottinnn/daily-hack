# X 告知画像の作り方

**X の告知に付ける画像は正方形（1080×1080）で作る。** ブログのアイキャッチ（1600×900）を
そのまま流用しない。タイムラインでの占有面積が違う。

生成: `node scripts/gen-sauna-x-cards.mjs`（記事ごとに複製して中身を差し替える）

## 2026-08-30 に受けた指摘

Jordan がサウナ記事の草案を見て出した指摘。**そのまま次の記事にも効く。**

| 指摘 | 直し方 |
| --- | --- |
| 1 投稿目と 2 投稿目の画像が同じ | **同じ画像を 2 度使わない。** 投稿ごとに別の絵を用意する |
| X 用に正方形にしたい | 1080×1080。[実績のある投稿](https://x.com/heng_ji31590/status/2088287574586790390) の形に揃える |
| 1 枚目はまとめの告知画像に | 開業する／した施設をまとめる。**記事冒頭のサマリーボックスを正方形の中に取り込む** |
| 2 枚目以降はアイキャッチではなく実物 | **実際にオープンした施設の写真**を記事内から使う |
| 全部で 4 枚 | 1 枚目＝まとめ、2〜4 枚目＝実際の施設 |
| 2 投稿目は記事の紹介に | スレッドの 2 本目で記事そのものを案内する |

## 1 枚目（まとめ）の作り

**記事の `.event-pick` を PIL で描き直さない。似て非なるものになる。**
`src/styles/global.css` の CSS をそのまま使い、Playwright で撮る。記事と完全に一致する。

```text
┌─ 濃紺の帯 ── kicker / 大見出し / サブ ────────┐
│  ピンク→オレンジのグラデ線                     │
│  ┌ カード ┐ ┌ カード ┐   ← .event-pick と同じ  │
│  └────────┘ └────────┘      （実写＋暗幕＋バッジ）│
│  ┌ カード ┐ ┌ カード ┐                        │
│  └────────┘ └────────┘                        │
│  黄色の注記ボックス（一番の驚きを 1 行で）      │
│  出典                             Daily Hack   │
└────────────────────────────────────────────────┘
```

濃紺の帯と黄色の注記は、実績のある「ららぽーと店舗売上ランキング」の画像に合わせている。

## 2〜4 枚目（実物）の作り

全面に施設写真、下に情報帯。**どの施設か一目で分かること**が要件。

- 左上にピンクの丸バッジで開業日、右上に `Daily Hack`
- 下に 施設名（大）／ 一行の売り／ 最寄・料金・男女のピル／ **出典**

## 出典は画像に焼き込む

施設写真は各施設の**公式サイト**から取っている（CC ではない）。
**X に出すと画像だけが独り歩きする**ので、記事の `figcaption` と同じクレジットを
画像の中に入れる。記事の外に出す画像は、記事の外でも出典が読めなければならない。

## 落とし穴

- **`page.setContent()` だと `file://` の画像が読めない。** origin が `about:blank` に
  なるため Chromium が下位リソースを拒む。画像と同じ階層に一時 HTML を置いて `goto` する
- 生成後に**背景画像が実際に読めたかを検査する。** 読めないと灰色のカードのまま出力され、
  **エラーも出ない**（2026-08-30 に実際に 1 度出した）
- Chromium は `/opt/pw-browsers/chromium-1194/chrome-linux/chrome` を直接指す。
  `playwright install` はしない（環境側で用意済み）
- 日本語フォントは Noto Sans JP を `~/.fonts` に置いて `fc-cache -f`

## 出す前に必ず自分の目で見る

`Read` で 4 枚とも開く。**ファイルサイズが増えただけでは中身の確認にならない。**
そのうえで Slack のスレッドへ実物を貼り、**画像を見たうえでの 👍**をもらう
（CLAUDE.md 最上位ルール 4「画像確認なしの投稿は絶対に許可されない」）。
