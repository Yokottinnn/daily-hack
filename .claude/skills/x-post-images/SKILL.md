# X 告知画像の作り方（daily-hack / @heng_ji31590）

**このスキルを読まずに X の告知画像を作らない。**

```bash
node scripts/gen-x-cards.mjs ops/data/x-cards/<slug>.json
```

**記事ごとにスクリプトを増やさない。** JSON を 1 本足せば作れる。

## 0. 絶対に外さない 7 つ

| # | ルール | 破ると |
| --- | --- | --- |
| 1 | **正方形 1080×1080。** ブログのアイキャッチ（1600×900）を流用しない | タイムラインでの占有面積が小さくなる |
| 2 | **同じ画像を 2 度使わない。** 投稿ごと・スレッドの位置ごとに別の絵 | 手抜きに見える。実際に指摘された |
| 3 | **2 枚目以降はアイキャッチではなく実写。** 記事内の実物写真を使う | 何の店か伝わらない |
| 4 | **出所の行は出さない**（2026-09-20）。だから**権利表記が要る素材を使わない**（§3） | 消すだけだとライセンス違反。素材ごと変える |
| 5 | **出す前に `Read` で全部開いて自分の目で見る** | 灰色の空カードが黙って出力される（実際に起きた） |
| 6 | **キャラを置いたら下端の切り口を見る。** `mask-image` で溶かす | 白いセーラー服の裾が四角い箱に見える（実際に指摘された） |
| 7 | **1 枚目の帯は、その場所の実写を薄く敷く**（`bgImage`）。**キャラは置かない** | どの記事でも同じ絵になり、帯を見ても どこの話か分からない（§1 が既定の作り方） |

## 1. 構成

| 位置 | 種類 | 中身 |
| --- | --- | --- |
| 1 枚目 | `cover` | **帯（背景に実写を薄く）** ＋ **カード格子** ＋ 黄色の注記（**出所は出さない**・§3） |
| 2 枚目〜 | `photo` | 実写を全面 ＋ 下に 施設名・売り・スペック（**出所は出さない**・§3） |

**カードは記事の `.event-pick`（`src/styles/global.css`）と同じ骨格。**

### 1 枚目の帯は、この作り方を既定にする（2026-09-05 に決定）

> これからもこの構図の画像はこの作り方にしよう

**帯の背景に、その記事の場所・施設の実写を薄く敷く。** キャラは置かない。

```jsonc
"cover": {
  "kicker": "2026年9月3日オープン",          // 時期・条件。短く
  "title":  "IKEA豊洲のゾーン別まとめ",       // 1 行に自動で収まる
  "sub":    "何がどこにあるか <em>6ゾーン全部</em>",
  "bgImage": "photos/zone-entrance.jpg",     // ← 帯の背景。imageBase からの相対パス
  "bgOpacity": 0.22,                         // 既定 0.22。0.12〜0.45 で調整
  "mark": false,                             // 温泉マークは出さない
  "columns": 2,
  "cards": [ /* 6 枚 */ ],
  "note":   "<b>いちばん効く一文。</b>補足",
  // **`source` は書かない**（§3）。`credit` も同じ
  "theme":  "plum"
}
```

**`mascot` は書かない。** 帯に敷けるものは 1 つで、写真とキャラを重ねると
見出しの後ろが混む。

| 帯に敷くもの | どんな記事か |
| --- | --- |
| **実写**（`bgImage`）**← 既定** | 場所・施設・店舗が主役。「そこに何があるか」を伝える記事 |
| キャラ（`mascot`） | 場所が無い抽象的なまとめ。実写の素材が無いとき |

**なぜ実写が既定なのか。** 帯を見た瞬間に「どこの話か」が伝わる。
キャラはどの記事でも同じ絵なので、**記事の区別がつかない。**

#### 外せない点が 3 つある

1. **スクリムを重ねる**（`.bgscrim`）。写真の明るい部分で `kicker` が沈む。
   生成側が自動で入れるので JSON には書かない
2. **借りている写真は敷かない。** 出所の行を出さないので、表記が要る素材は使えない（§3）
3. **素材に無いものを、有るように扱わない。** IKEA豊洲では
   **ららぽーとの外観写真が無かった**ので、店舗入口で代えた。
   **代えたことを利用者に言う**（黙って近い絵を使わない）

### cover のカードは 2 通り

| 使い分け | 出す情報 | JSON |
| --- | --- | --- |
| **施設・店舗を並べる**（既定） | 開業日バッジ／名前／場所と一言 | `badge` `title` `meta` |
| 数字で語る | 見出し語バッジ／数字／説明文 | `badge` `title` `desc` |

`columns` で列数、カード数から段数が決まる。**3 段以上になると自動で文字を詰める**
（`dense`）。6 枚なら `columns: 2` で 3 段。

## 1-B. 帯の配色（テーマ）

**紺は使わない。** ブログの `:root`（`src/styles/global.css`）のトークンだけを使う。

| 名前 | 地 | 向き |
| --- | --- | --- |
| `plum` | 濃いプラム `#2A1923` → `#46293A` | ブログの本文色そのもの。既定向き |
| `berry` | 濃いローズ `#A82959` → `#D63E76` | お得・食べ物。ピンクが一番強く出る |
| `rose` | 明るいピンク `#D63E76` → `#EC5C90` | 軽い話題。TL で目を引く |
| `cream` | クリーム `#FFF1C8` → `#FCE5A4`（**文字は濃いプラム**） | 反転。暗い画像が多い中で明るく浮く |
| `ink` | ほぼ黒 `#1E1219` → `#2A1923` | 数字・比較で締めたいとき |

```jsonc
"cover": { "theme": "rose", ... }
```

**書かなければ slug から自動で選ぶ。** 記事ごとに散り、同じ記事では毎回 同じ色になる。
**毎回 同じ色にしないこと自体がルール**（2026-09-05 の指摘）。

## 2. JSON の書き方

`ops/data/x-cards/<slug>.json`

```jsonc
{
  "imageBase": "public/images/<slug>",     // 画像の基準ディレクトリ
  "out": "public/images/<slug>/x",          // 出力先
  "cover": {
    "file": "1-summary.jpg",
    "kicker": "2026年オープン ／ 東京・神奈川・千葉・埼玉",
    "title": "首都圏のサウナ新店",
    "sub": "料金・最寄駅・男女別 <em>17施設まとめ</em>",   // em は黄色になる
    "bgImage": "facilities/maihama.jpg",  // ← 帯の背景に実写を薄く（既定。§1 参照）
    "bgOpacity": 0.22,                    // 既定 0.22
    "mark": false,                        // 温泉マーク。出すときだけ true
    "columns": 2,
    "cards": [
      { "img": "facilities/maihama.jpg", "badge": "♻️ 1/15",
        "title": "スパ＆ホテル<br>舞浜ユーラシア",           // br で折る
        "meta": "千葉・舞浜／70人収容の展望サウナ" }
    ],
    "note": "この6つを含めて<b>首都圏で17施設。</b>"        // b はオレンジになる
    // **`source` は書かない**（§3）
  },
  "photos": [
    { "file": "2-maihama.jpg", "img": "facilities/maihama.jpg",
      "badge": "♻️ 1/15 リニューアル", "name": "スパ＆ホテル 舞浜ユーラシア",
      "lead": "70人収容・<b>国内最大級の開口面積</b>の展望サウナ",
      "specs": ["千葉・舞浜", "2,100円〜", "男女"] }
      // **`credit` は書かない**（§3）。書かずに済む素材だけを使う
  ]
}
```

## 2-B. 右上のキャラと温泉マーク（**既定ではない**）

> **1 枚目の帯は実写が既定**（§1）。ここは**実写の素材が無いとき**と、
> 場所の無い抽象的なまとめのための逃げ道である。**`bgImage` と併用しない。**

`mascot` に `public/images/` 直下のファイル名を書くと、帯の右上に置く。

- **透過 PNG を選ぶ。** `expr-01`〜`expr-09` はアルファ付き。
  `mascot-avatar.png` は**アルファが無い**ので白い箱になる
- **透かしとして置く。** `cover.mascotOpacity`（既定 `0.38`）で濃さを決める。
  帯の中で**上下中央**に入り、下端は地に溶ける。
  元画像はバストアップで裾が真横に切れているので、**そのまま置くと四角い箱に見える**
- 表情は記事の空気で選ぶ。得意げなら `expr-05-smug`、応援なら `expr-04-cheer`
- **見出しは自動で 1 行に収まる。** 文字数からサイズを決め、11 文字以上は
  幅の上限を外して**透かしのキャラに重ねる**。`<br>` を入れる必要は無い
  （`cover.titleSize` で手動指定はできる）

温泉マーク（♨）は**画像を取りに来ず SVG で描いている。**

> Wikimedia Commons はクラウドセッションの egress ポリシーで塞がれている
> （`commons.wikimedia.org:443 connect_rejected`）。
> 記号自体は JIS の地図記号で形に著作権は無く、**描いたほうが確実で透過も解像度も自由。**
> ビットマップを拾うと縁が出るうえライセンス表記も要る。
> どうしても実物が要るなら `ops/tasks` 経由で Mac に取らせる（Mac からは届く）。

## 3. 出所の行は出さない。**だから素材のほうを選ぶ**

**2026-09-20 に指示された。**

> 出所不要。今後もいらないからメモリに記録して。

**`source` も `credit` も出さない。** 1 枚目の下端も、2 枚目以降の下端も空にする。

### 消すだけでは済まない

`credit` は**権利表記**で、**CC BY / CC BY-SA は表記がライセンスの条件**である。
黙って消すと違反になる。**だから素材のほうを変える。**

| 使ってよい（表記が要らない） | 使わない（表記が要る） |
| --- | --- |
| **CC0 / パブリックドメイン** | **CC BY**（表示） |
| **各社のロゴ**（商標・識別目的。CLAUDE.md 最上位ルール 17） | **CC BY-SA**（表示・継承） |
| **App Store 掲載素材**（記事で使っているもの） | 「引用（出典表記）」の素材 |
| **自分で作った図・合成** | 各施設の公式サイトから借りた写真 |

### 組む前にライセンスの一覧を見る

```bash
cat public/images/<slug>/photos/_manifest.json
```

**CC BY-SA しか無い題材なら、ロゴと数字のカードで組み直す。**
実際にそうした（2026-09-20・都心の格安スーパー）。写真 11 枚のうち使えたのは
**CC0 の 2 枚だけ**だったので、残りは各社ロゴの合成に置き換えた。

**`ops/data/x-cards/<slug>.json` の `_note` に「なぜ出所が無いか」を書き残す。**
あとから CC BY-SA を戻す人が、出所の行も戻せるように。

### ロゴを全面に使うときは、下を暗くする

ロゴは白背景のものが多く、**明るい画像になって白い見出しが埋もれる**（実際に埋もれた）。

| | やること |
| --- | --- |
| 全面用（1080×1080） | **下 40% を暗くしてから**文字を乗せる |
| カード用（1000×560） | **絵を上側に置く**（下半分に濃いグラデーションと文字が来る）。横は `cover` で**左右 17% ずつ切れる**ので中央 66% に収める |

## 4. 落とし穴（全部 実際に踏んだ）

| 症状 | 原因 | 対処 |
| --- | --- | --- |
| **カードが灰色。エラーも出ない** | `page.setContent()` だと origin が `about:blank` になり、Chromium が `file://` の下位リソースを拒む | 画像と同じ階層に一時 HTML を置いて `goto`。生成側で**背景が読めたか検査**して読めなければ `throw` |
| `playwright install` を促される | npm 版と入っている Chromium の版が揃わない | **install しない。** `/opt/pw-browsers/chromium-1194/chrome-linux/chrome` を直接指す |
| 日本語が豆腐 | フォントが無い | Noto Sans JP を `~/.fonts` に置いて `fc-cache -f` |
| 文字がカードからはみ出す | 段数が増えた | `columns` を調整。3 段以上は自動で詰まるが、`title` は `<br>` で自分で折る |

## 5. 出したあと

1. **`Read` で全部開いて見る。** ファイルサイズが増えただけでは確認にならない
2. **`SendUserFile` でこのチャットに実物を添付する。**
   - **Slack には貼らない**（2026-09-05 に廃止。コネクタが添付できず、
     `ops/tasks` を挟むと確認までに数十分かかっていた。CLAUDE.md 最上位ルール 4）
   - **ファイルパスを書いただけでは「画像を出した」ことにならない**
3. **画像を見たうえでの承認をもらってから投稿する**
4. **投稿タスク側では、画像を `git show origin/main:<path>` から取り直す。**
   Mac の作業ツリーは main とは限らず、**絵を直しても取り直さないと古い絵が出る**
   （2026-09-05 に踏みかけた）

> **画像確認なしの投稿は絶対に許可されない**（CLAUDE.md 最上位ルール 4）。
> 文面だけの草案に 👍 が付いても、それは投稿の許可ではない。
