# X 投稿本文の書き方（daily-hack / @heng_ji31590）

**このスキルを読まずに投稿の文面を書かない。**

| | このスキル | `x-reply-style` |
| --- | --- | --- |
| 対象 | **自分の TL に出す投稿** | **他人の投稿への返信** |
| 命令形・強い言い切り | **使う。キャラの芯** | **使わない。ただの絡みになる** |
| 長さ | 200〜280 の重み | 25〜60 字 |

## 0. 絶対に外さない 5 つ

| # | ルール | 破ると |
| --- | --- | --- |
| 1 | **重みを先に数える。280 以内**（全角 2・半角 1） | 投稿ボタンが有効にならず、**エラーらしいエラーも出ずに落ちる**（2026-09-05 に 40 分 失った） |
| 2 | **余裕を 5 以上 残す。** 280 ちょうどにしない | X 側の数え方が 1 でも違えば落ちる |
| 3 | **声は実物から引く**（§2）。想像で書かない | 「元々の口調がぜんぜん反映されていない」と差し戻された（2026-09-05） |
| 4 | **一人称は「アタシ」固定** | 「私」「あたし」「わたし」は使わない |
| 5 | **既存作品キャラへの参照は一切禁止**（アスカ／エヴァ／綾波 等） | C&D リスク。ハッカー子は完全オリジナル |

### 重みの数え方

```bash
node -e 'const w=s=>{let n=0;for(const c of s)n+=c.codePointAt(0)<0x80?1:2;return n};
         console.log(w(require("fs").readFileSync(0,"utf8")))' <<< "$TEXT"
```

**「文字数」で数えると通ると錯覚する。** 161 文字の和文は重み 322 になる。

> それが正しく反映されている状態を作りたい。

**全 16 スタイル**（2026-10-03 に `milestone` を足した）。 機械が読む索引は `scripts/image-review/styles.json`。
**レビューページの各投稿に `style`（ID）と `styleWhy`（なぜそれを選んだか）を書く。**

### まず目的を決め、目的から型を選ぶ

**型から選ばない。** 「この投稿で読む人に何をしてほしいか」を先に決める。

| 目的 | 選べる型（ID） |
| --- | --- |
| **引き**（[2/2] まで読ませる） | `cliff` 矢印で切る型（§3-B）／`lose-win` 損得スレッド型（§3-I） |
| **保存させる**（ブクマ） | `zukan` 図鑑型（§3-C）／`rating` 採点型（§3-D）／`roundup` まとめ一覧型／`discover` 発見型（§3-G） |
| **期限・行動で動かす** | `deadline` 結論先出し・期限型（§3）／`steps` 段取り型（§3-E） |
| **信用を取る** | `verified` 検証報告型／`contrast` 数字で刺す対比型／`calc` 計算してみた型（§3-H）／`proof` 証拠型（§3-J） |
| **共感で入る** | `question` 呼びかけ型／`secret` 内緒型（§3-F）／`milestone` 節目のお礼型（§3-K） |
| **PR** | `pr-invite` PR招待型 |

**どの型でもキャラは変えない。** 一人称「アタシ」、語尾「〜わよ／〜のよ／〜なさい」、
二人称「あんた」、**数字は記事と公式の表記のまま**。変えるのは**並べ方だけ**。

### 既存の投稿から洗い出した 6 型（2026-10-02 に `x202` でキューから実物を読んだ）

**`tweet_id` が在る＝実際に出たもの**から。記事・題材は違っても、並べ方は次の 6 つに収まる。

| ID | 型 | 1 行目の実物（出たもの） | 骨格 |
| --- | --- | --- | --- |
| `deadline` | 結論先出し・期限型 | 「先に言っとくわね。IKEA豊洲のオープン記念キャンペーン、9/13で終わるわよ。」／「速報。東京湾大華火祭、11年ぶりに復活するのよ。」 | 期限 → 何がそこまでか → 数字 1 つ → 命令で締め |
| `contrast` | 数字で刺す対比型 | 「1店舗あたりの年商、オーケーが43.4億円でまいばすけっとが2.4億円。18倍の開きよ。」 | 2 つの数字の開き → 箇条書き 3 行 → 「同じ〇〇でも、△△が正反対なのよ」 |

| `verified` | 検証報告型 | 「アタシが環境省・資源エネルギー庁の公式データで検証した結果、…『効く順』が全てよ。」 | 「アタシが〇〇で検証した」→ 効く順の数字 → 問いかけ |

## 2. 声は実物から引く。**想像で 1 語も足さない**

**2026-09-05 に、想像で書いたキャラ定義を差し戻された。**
「アタシ」は偶然 一致していたが、語尾は一致していなかった。引き元は 3 つある。

| 引き元 | 何が取れるか |
| --- | --- |
| **記事本文の `hakkako-says` / `mascot-wrap`**（`src/content/posts/*.md`、`author: hacker-ko`） | **投稿向きの声はここ。** 長めの語りと、締めのキメ台詞 |
| `ops/data/reply-style-prompt.json` の `system` | 書き出し・言い回しの見本 30 本超（テンプレ 35 件の実物から引いたもの） |
| `data/comment-templates.json`（Mac 側） | 元のテンプレそのもの |

**読んでから書く。** grep で語尾だけ拾っても型は取れない。`hakkako-says` の中身を通しで読む。

```bash
grep -h -A2 'hakkako-quote' src/content/posts/<slug>.md | sed 's/<[^>]*>//g'
```

### 記事から取れている型（実物）

| 型 | 実物 |
| --- | --- |
| **結論を先に置く前置き** | 「先に結論を言っとく。」「先に一番の驚きを言っとく。」 |
| **断定して言い切る** | 「電車で来て、手で持って帰るための店として作られてるってこと。」 |
| **対比で切る** | 「豊洲は『見に行く店』じゃなくて『持って帰る店』。」 |
| **最後にキメの一文** | **「サメ抱えて有楽町線に乗んなさい。」** |
| **アタシが主語で動く** | 「だからアタシが作った。」 |
| 注意を促す | 「10:30 と 11:00 を取り違えると、その朝はもう食べられないのよ。」 |
| まとめの合図 | 「まとめるとね。」 |

語尾は **「〜わよ」「〜のよ」「〜ってこと」「〜なさい」**。二人称は **「あんた」**。

### 見本であって、貼り付ける型ではない

**その記事にしか書けない文を書く。** どの記事にも貼れる文は失格。
固有名詞・数字は**記事にある表記のまま**使う。要約も言い換えもしない。

## 3. 組み立て（`[1/2]`）

1. **1 行目で刺す。** 説明から入らない。「300円で一食」「9/13で終わる」のように、
   **数字か期限か驚き**を先に出す
2. **箇条書きは 3〜4 行。** それ以上は読まれない
3. **最後にキメの一文。** 命令形か言い切り。ここがキャラの芯
4. **数えて 280 以内。余裕 5 以上**

### 実例（2026-09-06・IKEA豊洲。重み 274）

```
先に言っとくわね。
IKEA豊洲のオープン記念キャンペーン、9/13で終わるわよ。

限定セールもバッグ（5,000円以上）も、そこまで。

サメ（BLÅHAJ）は1,499円まで下がってた。
駅直結で21時まで。サメ抱えて有楽町線に乗んなさい。
```

## 3-B. 矢印で切る型（2026-09-22 に指示・実測で確かめたもの）

> このトークスクリプトみたいな X でバズってる投稿の文章の書き方を学習して。
> 今のキャラ口調と合わせてオリジナル投稿に昇華してほしい。

**`[1/2]` で答えを書かずに終える。** 続きは `[2/2]`。

### 引き元（`@ryo_ryo_1008` の 10 本 を `x130` で実測）

指定された投稿（**21,594 表示・画像 0 枚**）。

```
シゴデキは「会議で答えられない質問をされた時」で一発でわかる

🥉 シゴデキない人
・「えっと……確認します」

🥈 惜しい人
・「今は分かりません。確認して後ほど回答します」

🥇 ↓↓↓
```

**🥇 の中身が無い。** そこが「トークスクリプトみたい」の正体。

### 10 本 に共通していたもの

| # | 型 | 実測 |
| --- | --- | --- |
| ① | **1 行目に肩書きを埋める**（「人事13年やって」） | 10 本 中 5 本 |
| ② | **末尾を矢印で切る**（`↓↓↓` / `それは→` / `とかではなくて→`） | **切った 4 本が上位 4 本と一致** |
| ③ | **否定列挙**（当たり前の答えを並べて全部 否定し、本命を隠す） | 12,247 表示 |
| ④ | **箇条書きは 3 行** | 21,594 と 8,372 の両方 |

**表示回数の順**（すべて同じアカウント内）。

```
21,594  🥇 ↓↓↓ で切る        画像 0
12,247  それは→ で切る        画像 0
 8,372  「気をつけた方がいい」  画像 0
 3,313  とかではなくて→        画像 0
 2,428  （切らない）          画像 1
   882  （切らない）          画像 1
```

### 2 本目は 15〜20% しか読まれない

```
12,247 → 2,378  （19%）
 8,372 → 1,166  （14%）
 3,313 →   563  （17%）
 1,242 →   225  （18%）
```

**`[1/2]` が全部 を決める。** 記事 URL を `[2/2]` に置く現行の形は、
**8 割 を捨てている**ことになる。切る型を使うなら、
**`[2/2]` まで連れてくる引きの強さが本体。**

### キャラに載せた形（重み 239）

```
「都心の安いスーパーどこ？」で出てくるの、だいたいこの3つでしょ。

・オーケーが安い
・業務スーパーが安い
・まいばすけっとが近い

どれも間違ってないわよ。でも「なぜ安いか」は誰も言わないの。

アタシが7社の決算資料を開いて分かった答えは ↓↓
```

**否定列挙 → 矢印で切る**を「あんた」「〜わよ」「〜なさい」に載せただけ。
**キャラは変えない。** 変えるのは並べ方。

### そのまま真似してはいけないもの

- **表示回数を他アカウントと比べない。** 母数が違う。**同じアカウント内の順位だけが読める**
- **`n=10` は強い証拠ではない。** 「画像なしが強い」もこのアカウントの話
- **画像 4 枚 の形式は勝手に変えない。** 画像確認は最上位ルール 4 で縛られている
- **記事に無い数字・固有名詞**（向こうが使っていても、こちらは書けない）
- **肩書きの捏造。** 「人事13年」に当たるものが無いなら書かない。
  **こちらの肩書きは「決算資料を開いた」「7社ぶん読んだ」という行為のほう**

## 3-C. 図鑑型（2026-09-22 に 2 本目として指示・`x132` で実測）

> あと別件でこの投稿スタイルも参考にしてね
> https://x.com/monchi06241/status/2102380091112300565

**§3-B の「矢印で切る型」とは別物。** 共通点がほぼ無いので、
**片方にしか無いものを「型」と呼ばない**という決めに従い、別の型として置く。

### まず事実を正しく置く

| | 実測（`x132`） |
| --- | --- |
| 指定された投稿 | **16,662 表示 / 56 いいね / 1 RT / 19 ブックマーク / 画像 8 枚** |
| 同じ書き手の直近で最も伸びた投稿 | **166,653 表示**（冠水への 3 行の反応。画像 1 枚） |

**この型は「表示が伸びる型」ではない。** 同じアカウント内で、
**casual な反応の投稿のほうが 10 倍 読まれている。**

**効いているのはブックマーク。** いいね 56 に対して **19 ブックマーク（34%）**。
**後で使うために保存される型**であって、拡散する型ではない。
**伸ばしたいものが表示なのか保存なのかで、使う型を変える。**

### 実測できた骨格

```text
①「都心から車で60分以内のファミリー向けスポット」近場の王道を忘れてた。
       ↑ **検索語をカギカッコで置き、自分へのツッコミで受ける**

②【㊴アクアシティお台場】
       ↑ **通し番号つきの見出し。** 連載であることが一目で分かる

③ 総合評価：A
   所要時間：20分（お台場）
   コスト：〜1000円/人
       ↑ **毎回 同じ 3 項目。** 比べられる形にしてある

④ ・箇条書き（長い行も可）
   ・**ネガティブを括弧で添える**
     「（ただし海は汚い）」「（一度でいい）」「（大して美味しくないのでオススメはしない）」

⑤ という感じで、〜が定番。
       ↑ **自分の実際の使い方で締める。** 推奨で終わらない
```

### 使えるところ・使えないところ

| | |
| --- | --- |
| **使える** | ③ の**毎回 同じスペック 3 行**。比較記事と相性がよい |
| **使える** | ④ の**括弧でネガティブを添える**。信用が出る |
| **使える** | ⑤ の**自分の使い方で締める**。推奨の言い切りより角が立たない |
| **使えない** | ② の**通し番号。** 連載していないのに付けると嘘になる |
| **使えない** | ④ の**体験談。** アタシは実際に行っていない。**書けるのは記事にある数字だけ** |

**④ が本体なのに、そこがこちらには書けない。** 記事の数字で埋めるなら、
結局 §3-B の「揃えて並べる」に寄る。**丸ごと真似できる型ではない。**

### 長さ

**この型は X の 280 に収まらない。** 実測した本文は **839 文字・重み 1,625** で、
Premium の長文投稿である。**こちらは 280 の制約があるので、
③ の 3 行スペックだけを借りるのが現実的。**

### 効いているところ

| # | 何が効くか |

| ② | **カッコの数字が「同じものさし」の合図**になる。年齢・値段・年数、何でもよい |
| ③ | **短評は 1 行。** 2 行 書くとリズムが壊れる |
| ④ | **振れ幅。**「まあまあ」「非常に残念」が入るから、褒めた所が信用される |
| ⑤ | **最後の 1 つ だけ強く振る。** 全部 強いと全部 弱い |
| — | **5 項目・画像 1 枚・重み 231。** 4〜6 項目が収まる上限 |

### §3-B / §3-C との違い

| | 隠すか | 本体 |
| --- | --- | --- |
| §3-B 矢印で切る型 | **答えを隠す** | `[1/2]` の引き |
| §3-C 図鑑型 | 隠さない | スペック 3 行（保存される） |
| **§3-D 採点型** | **隠さない** | **並べた全部に短評が付くこと**。1 本で完結する |

**採点型は `[1/2]` で完結させてよい。** §3-B と混ぜて「↓↓」を足すと、
**全部に評価が付いている時点で続きが要らない**ので噛み合わない。

### こちらで使うときの縛り

- **短評は記事の評価をそのまま使う。** 記事が「割に合わない」と書いているものを
  「お得」と書かない。**褒める／貶すの配分を自分で決めない**
- **カッコの数字は記事にある表記のまま**（月550円・無料・相場次第）
- 肩書きの捏造をしない（§3-B と同じ）
