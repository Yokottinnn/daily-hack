**このスキルを読まずに返信文を書かない・返信量を変えない。**

## 0. 絶対に外さない 5 つ

| # | ルール | 破ると |
| --- | --- | --- |
| 1 | **見下し・詰問の型を他人へ向けない。** アカウント名の「あんたバカぁ？」は自分の TL の芸であって、他人の投稿への返信では絡み | 通報・ブロック。1 件で終わる |
| 2 | **相手が損・失敗・トラブルを報告している投稿には、茶化しも「損してる」も使わない** | 傷口を踏む。最も燃えやすい |
| 3 | **金額・利率・「得する」を断定しない。** 条件と時期を必ず付ける | 金融助言と読まれる。ジャンルが実害の出る領域 |
| 4 | **弾くのは相手だけでなく自分の文も。** 送信前に必ずトーン検査を通す | NG フィルタは相手を弾くだけ。**自分の文は誰も見ていない** |
| 5 | **返信量を増やす前に、まず文面を直す** | 危ない文の本数が倍になるだけ |

## 1. なぜヒヤヒヤするのか（2026-08-27 の自己分析）

**推定と実測を分ける。** 断定できるものだけ断定する。

### 実測で分かっていること

| 事実 | 出典 |
| --- | --- |
| 返信は 1 日 8 件（`MAX_PICKS_PER_FIRE=2` × 発火 4 回） | `reports/conversion.md` |
| 相手の選定条件は **`MIN_LIKES=2` / `MAX_AGE_HOURS=18`** だけ | `ai.openclaw.comment-warmup.plist` |
| テンプレートは **37 件の固定リスト**（`data/comment-templates.json`） | `reports/reply-structure.md` |
| 選び方は重み付け＋直近の重複回避（`RECENT_TEMPLATE_IDS`） | `asuka-fill.js` |
| 返信をきっかけに 1 日 7 件フォローしている | `comment-orchestrator.log` |

### 危ないと考える理由（推定を含む）

1. **人格そのものが攻撃形になっている。**
   アカウント名が「あんたバカぁ？まだ損してるの？速報💸」。自分の投稿では持ち味だが、
   **これを他人の投稿への返信に持ち込むと「知らない人に急にバカと言われた」になる。**
   同じ言葉でも、自分の TL で言うのと相手の TL で言うのは別物。

2. **相手の投稿の「状態」を見ていない。**
   選定条件は いいね数 と 経過時間 だけ。**相手が何を書いているかで分岐していない。**
   節約の失敗談・出費の後悔・家計の相談に「まだ損してるの？」が当たると嘲笑になる。

3. **金銭の断定が入りやすい。**
   ポイ活・NISA・ふるさと納税は**間違えると相手が実際に損をする**領域。
   「〜すれば得」と言い切ると、条件が違う相手には誤情報になる。

4. **37 件の使い回しが業者に見える。**
   同じ文面が複数の人に当たると、並べて見た第三者にスパムと判定される。

5. **出力側に検査が無い。**
   2026-08-27 に売春系アカウントを弾く `ng-filter-candidates.cjs` を入れたが、
   あれは**相手を弾く**もの。**こちらが出す文は無検査で X に出ている。**

> **5 が構造上の穴。** 入口だけ塞いで出口を塞いでいない。

## 2. 使ってはいけない型

| 型 | 例 | なぜ |
| --- | --- | --- |
| 見下し・詰問 | 「あんたバカぁ？」「まだ〜してるの？」「知らないの？」 | 他人へ向けると絡み |
| 決めつけ | 「それ損してますよ」「やめたほうがいい」 | 相手の事情を知らない |
| 金額・利率の断定 | 「年 3 万得します」「絶対に還元率が上」 | 条件次第で嘘になる |
| 煽り・不安喚起 | 「知らないと大損」「今すぐやらないと」 | 情報商材の型 |
| 命令 | 「〜しろ」「〜すべき」 | 頼まれていない |
| 過剰な絵文字 | 💸🔥😱 を 3 個以上 | スパム判定の材料 |
| 自分のリンクを貼る | 記事 URL を返信に入れる | 宣伝目的の返信と見なされる |

## 3. 相手の投稿の状態で分岐する

**同じテンプレートを全員に当てない。** 最低限この 3 分岐を持つ。

| 相手の投稿 | 取るべき態度 | 例 |
| --- | --- | --- |
| **損した・失敗した・困っている** | 茶化さない。同意か、条件付きの情報だけ | 「これ自分もやりました。◯◯の場合は△△が使えるみたいです」 |
| **成功した・得した報告** | 素直に乗る。上書きしない | 「その使い方いいですね。◯◯でも同じことできますよ」 |
| **単なる情報共有・雑談** | 一言足すだけ。長くしない | 「知らなかったです、助かります」 |

**迷ったら 3 番目（短く同意）。** 何も足せないなら**返信しないほうが良い。**

## 4. 出力側のトーン検査（作るべきもの）

`ops/lib/ng-filter-candidates.cjs` が**入口**なら、これが**出口**。

```text
候補 → ng-filter（相手を弾く） → 文面生成 → tone-check（自分の文を弾く） → 投稿
                                                    ↑ ここがまだ無い
```

要件は `ng-filter` と同じ思想で揃える。

- **判定できないときは通す**（ジョブごと落とさない）。ただし**理由をログに残す**
- 弾いた語と理由を stderr に出す。何が起きたか後から読めるようにする
- ルールは JSON（`ops/data/reply-tone-rules.json`）に置き、コードに埋めない

## 5. 返信量を変えるときの順序

**量は最後。** 文面 → 検査 → 量。

1. 実際に出している文面を持ち帰って読む（`ops/tasks/032-dump-reply-samples.sh`）
2. 危ない型を含むテンプレートを外す・書き換える
3. 出力側のトーン検査を入れる
4. **そのうえで**量を上げる

**2026-08-27 時点では 1 の途中。** `MAX_PICKS_PER_FIRE` を 2 から上げるのは
3 が終わってから。スクリプトは書いてあるが `ops/pending/031-double-replies.sh` に
置いてあり、**`ops/tasks/` に無いので実行されない**（`ops-heartbeat.sh` が拾うのは
`ops/tasks/*.sh` だけ）。**文面を直してから `ops/tasks/` へ動かす。**
