## 0. 絶対に外さない 5 つ

| # | ルール | 破ると |
| --- | --- | --- |
| 1 | **見下し・詰問の型を他人へ向けない。** アカウント名の「あんたバカぁ？」は自分の TL の芸であって、他人の投稿への返信では絡み | 通報・ブロック。1 件で終わる |
| 2 | **相手が損・失敗・トラブルを報告している投稿には、茶化しも「損してる」も使わない** | 傷口を踏む。最も燃えやすい |
| 3 | **金額・利率・「得する」を断定しない。** 条件と時期を必ず付ける | 金融助言と読まれる。ジャンルが実害の出る領域 |

| 5 | **返信量を増やす前に、まず文面を直す** | 危ない文の本数が倍になるだけ |

## 2. 使ってはいけない型

| 型 | 例 | なぜ |
| --- | --- | --- |
| **紹介コード・招待コード・アフィリンク** | 「紹介コード ZOAQ61 入力して」 | **X のスパムポリシー違反。凍結すれば全ループが止まる。実際に出した（2026-08-25）** |
| 見下し・詰問 | 「あんたバカぁ？」「まだ〜してるの？」「知らないの？」 | 他人へ向けると絡み |
| 決めつけ | 「それ損してますよ」「やめたほうがいい」 | 相手の事情を知らない |
| 金額・利率の断定 | 「年 3 万得します」「絶対に還元率が上」 | 条件次第で嘘になる |
| 煽り・不安喚起 | 「知らないと大損」「今すぐやらないと」 | 情報商材の型 |
| 命令 | 「〜しろ」「〜すべき」 | 頼まれていない |
| 過剰な絵文字 | 💸🔥😱 を 3 個以上 | スパム判定の材料 |
| 自分のリンクを貼る | 記事 URL を返信に入れる | 宣伝目的の返信と見なされる |

## 3. 相手の投稿の状態で分岐する

**同じテンプレートを全員に当てない。** 最低限この 3 分岐を持つ。

| 相手の投稿 | 取るべき態度 | 例 |
| --- | --- | --- |
| **損した・失敗した・困っている** | 茶化さない。同意か、条件付きの情報だけ | 「これ自分もやりました。◯◯の場合は△△が使えるみたいです」 |
| **成功した・得した報告** | 素直に乗る。上書きしない | 「その使い方いいですね。◯◯でも同じことできますよ」 |
| **単なる情報共有・雑談** | 一言足すだけ。長くしない | 「知らなかったです、助かります」 |

**迷ったら 3 番目（短く同意）。** 何も足せないなら**返信しないほうが良い。**

## 4. 出力側のトーン検査

`ops/lib/ng-filter-candidates.cjs` が**入口**なら、これが**出口**。

```text
候補 → ng-filter（相手を弾く） → 文面生成 → tone-gate（自分の文を弾く） → 投稿
```

| ファイル | 役割 |
| --- | --- |
| `ops/data/reply-tone-rules.json` | 何を弾くか。**コードに埋めない** |
| `ops/lib/reply-tone-check.cjs` | 判定だけ。`checkTone(text, rules)` |
| `ops/lib/tone-gate.cjs` | `asuka-fill.js` の出力を受け、危なければ `ok:false` にして返す |

### block と warn を分ける

**弾きすぎると返信が 0 件になる。** 命令形はテンプレ本体に含まれているので、
block にすると大半が落ちる。だから**凍結・炎上に直結するものだけ block** にする。

| 判定 | 対象 | 挙動 |
| --- | --- | --- |
| **block** | 紹介コード / URL / 見下し / 闇バイト語 / 未成年への説教 / 空文 | **送らない** |
| **warn** | 命令形 / 金額断定 / 日本語の重複 / 絵文字 4 個以上 / 140 字超 | 送るが記録する |

warn は溜まった数を見て**テンプレ側を直す判断材料**にする。
`repeat` はブランド名が並ぶと誤検知するが、warn は送信を止めないので実害は記録だけ。
**取りこぼすより過検知に倒す。**

### 失敗したときにどちらへ倒すか

```text
ルールや判定モジュールが読めない  → 素通し（今日と同じ状態に戻るだけ）
入力が JSON として読めない        → 素通し（呼び出し側の形を壊さない）
文が読めて block に当たった       → 弾く（ok:false）
```

**設備の故障では止めない。中身が危なければ止める。**
`throw` は一切しない。ここで投げると返信ジョブごと落ちる。

### 差し込み方

`comment-orchestrator.sh` の `asuka-fill.js` の直後、`enqueue` の直前。

```bash
GEN_OUT=$(... asuka-fill.js ...)
GEN_OUT=$(printf '%s' "$GEN_OUT" | /usr/local/bin/node scripts/tone-gate.cjs 2>>"$LOG")
```

## 5. 返信量を変えるときの順序

**量は最後。** 文面 → 検査 → 量。

1. 実際に出している文面を持ち帰って読む（`ops/tasks/032-dump-reply-samples.sh`）
2. 危ない型を含むテンプレートを外す・書き換える
3. 出力側のトーン検査を入れる
4. **そのうえで**量を上げる

**2026-08-27 時点では 1 の途中。** `MAX_PICKS_PER_FIRE` を 2 から上げるのは
3 が終わってから。スクリプトは書いてあるが `ops/pending/031-double-replies.sh` に
置いてあり、**`ops/tasks/` に無いので実行されない**（`ops-heartbeat.sh` が拾うのは
`ops/tasks/*.sh` だけ）。**文面を直してから `ops/tasks/` へ動かす。**
